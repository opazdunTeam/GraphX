# Каталог и приоритет источников

## 1. Назначение каталога

Каталог фиксирует продуктовую роль источников и порядок их проверки. Он не заменяет внутреннюю базу `Open-source databases.xlsx`: база остаётся расширенным рабочим перечнем, а этот документ содержит отобранные источники и принятые приоритеты.

Статусы:

- **MVP** — входит в целевой объём первой версии;
- **условный MVP** — вызывается только при наличии соответствующего объекта;
- **следующий этап** — приоритетен после основного контура;
- **исследовать** — полезность или доступ требуют проверки;
- **не использовать как основу** — допустим для обнаружения, но не для фундаментального получения данных.

Техническая доступность, тарифы и лицензии могут изменяться. Их необходимо повторно проверить перед реализацией и коммерческим использованием.

## 3. Карточки источников MVP

### ICIJ Offshore Leaks Database

**Назначение:** обнаружение лиц, офшорных организаций, посредников, адресов и опубликованных между ними связей.

**Ценность для MVP:** открытый и содержательный набор позволяет проверить полный цикл локального импорта, поиск транслитераций, сопоставление объектов и выдачу доказательств. В тесте по Александру Яковлевичу Клебанову обнаружены записи и связи с организациями; одновременно тест показал, что внешний коэффициент похожести нельзя принимать за окончательное решение.

**Доступ:** официальные выгрузки и сервис сопоставления. Документация: [загрузка данных](https://offshoreleaks.icij.org/pages/database), [Reconciliation API](https://offshoreleaks.icij.org/docs/reconciliation).

**Темпоральность:** отдельные записи и наборы имеют даты и период покрытия, но год актуальности набора нельзя подменять периодом конкретного отношения.

**Ограничения:** сведения происходят из отдельных расследовательских массивов и не являются полным реестром. Совпадение имени требует независимой проверки.

**Роль:** источник обнаружения и расширения; иногда подтверждение факта упоминания, но не автоматическое доказательство актуального владения.

### OpenSanctions

**Назначение:** санкционные списки, PEP, связанные лица и организации, нормализованные идентификаторы и происхождение отдельных сведений.

**Ценность для MVP:** готовая модель сущностей, варианты имён и механизм сопоставления позволяют сравнить собственный контур с отраслевым решением. Тест по Тимуру Руслановичу Турлову показал полезность псевдонимов, дат рождения, санкционных периодов и корпоративных отношений.

**Доступ:** размещённый API либо Bulk-набор и самостоятельный сервис. Официальная документация: [API](https://www.opensanctions.org/docs/api/), [Bulk](https://www.opensanctions.org/docs/bulk/).

**Темпоральность:** отдельные свойства и санкционные записи содержат даты. Служебная дата изменения набора не обязательно является датой события в первоисточнике.

**Ограничения:** ложное совпадение по распространённому имени является ожидаемым риском. Для коммерческого применения требуется отдельная проверка лицензии; бесплатное использование Bulk ограничено некоммерческими сценариями.

**Роль:** опорный источник screening, идентификации, расширения и подтверждения происхождения.

### OpenCorporates

**Назначение:** поиск компаний, регистрационных данных и должностных лиц по множеству юрисдикций.

**Ценность для MVP:** помогает перейти от человека к компаниям и от компании к её регистрационному контексту без разработки отдельного адаптера для каждой страны.

**Доступ:** REST API с ключом согласно [официальной документации](https://knowledge.opencorporates.com/knowledge-base/api-documentation/).

**Темпоральность:** зависит от исходной юрисдикции и конкретного поля; текущую карточку нельзя считать полной историей.

**Ограничения:** полнота и свежесть различаются по странам. Условия доступа, лимиты и совместимость лицензии должны быть проверены перед реализацией и коммерческим использованием.

**Роль:** опорный источник компаний и источник расширения; значимые сведения желательно подтверждать реестром соответствующей юрисдикции.

### КГД Республики Казахстан

**Назначение:** проверка налогоплательщика и доступных регистрационных статусов по ИИН или БИН.

**Ценность для MVP:** официальный источник основной юрисдикции с сильным идентификатором и датами начала или окончания статуса.

**Доступ:** документированный GET API; для запроса требуется `X-Portal-Token`, выдаваемый по обращению. Официальная [инструкция API поиска налогоплательщика](https://portal.kgd.gov.kz/en/pages/api-services/find-taxpayer/).

**Темпоральность:** в ответах предусмотрены даты начала и окончания для отдельных регистрационных сведений.

**Ограничения:** основной поиск зависит от наличия ИИН/БИН; порядок получения токена и допустимое использование требуется подтвердить.

**Роль:** официальный источник идентификации и подтверждения статуса в Казахстане.

### Kazakhstan Stock Exchange — KASE

**Назначение:** эмитенты, ценные бумаги, корпоративные сведения, раскрытия и документы.

**Ценность для MVP:** документы биржи позволяют восстанавливать назначения, прекращения полномочий и состояния органов управления. Тесты по Александру Клебанову и Тимуру Турлову показали наличие исторических должностей и дат.

**Доступ:** IRIS API и публичные документы. KASE публикует [описание IRIS API](https://kase.kz/uploads/iris_api_v2_24_00_eng_dc5af7c4f4.pdf); конкретные условия и доступные методы проверяются перед подключением.

**Темпоральность:** высокая ценность у датированных раскрытий. Формулировка «по настоящее время» ограничивается датой документа.

**Ограничения:** источник относится прежде всего к эмитентам и не заменяет общий реестр компаний. Часть информации находится в документах и требует извлечения с указанием фрагмента.

**Роль:** исторический источник и источник подтверждения корпоративных ролей.

## 4. Условные источники MVP

### SEC EDGAR

Подключается при наличии связи с публичной компанией или раскрытием в США. SEC предоставляет открытые JSON API и ночные Bulk-архивы истории подач и XBRL-данных без API-ключа; документы остаются первичными доказательствами. Официальная [документация EDGAR Data APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces).

Источник полезен для истории директоров, владельцев и корпоративных событий, но не должен вызываться для каждого расследования без американского контекста.

### RDAP

Используется при обнаружении домена. Для gTLD регистрационные сведения следует получать через RDAP, ставший основным протоколом вместо WHOIS. Официальная [информация ICANN о RDAP](https://www.icann.org/rdap/).

Публичные сведения могут быть ограничены политиками раскрытия и защитой персональных данных. Совпадающий регистрант или технический контакт является признаком, а не автоматическим доказательством владения компанией.

## 5. Источники следующего этапа

### Казахстан

- **ОПИ ДФО и порталы открытых данных** — отобрать конкретные наборы с устойчивыми файлами или API, понятными владельцами и датами обновления.
- **Судебный кабинет и судебные публикации** — провести отдельную проверку доступности, условий автоматизации, структуры документов и допустимости обработки персональных данных.
- **Иные источники из листа Kazakhstan** — ранжировать по уникальному вкладу, а не по количеству доступных ссылок.

### Кыргызстан

Приоритет — официальный сервис Министерства юстиции с данными о компаниях и владельцах. До реализации необходимо подтвердить действующие способы доступа, ограничения поиска и возможность автоматизации.

### Узбекистан

Республиканская фондовая биржа «Тошкент» полезна для эмитентов и раскрытий. iHamkor рассматривается как коммерческий источник поиска компаний. Эти источники подключаются после устойчивого казахстанского контура.

### Россия

Основой должны быть первичные или официальные системы: ФНС России, ГИР БО, Федресурс, официальные судебные источники и раскрытия. Rusprofile, List-Org, C-Firm и аналогичные агрегаторы могут помогать обнаруживать направление поиска, но не должны быть единственным фундаментом из-за производности данных, условий доступа и нестабильности парсинга.

Интерфакс и Центр раскрытия корпоративной информации полезны для событий и документов; официальный API рассматривается как коммерческое расширение.

### Кипр и ОАЭ

Официальные реестры из соответствующих листов внутренней базы следует оценивать по доступности выписок, идентификаторам, владельцам, историческим документам, цене и лицензии. ICIJ не заменяет государственный реестр, но может дать исходные кандидаты для проверки.

## 6. Источники обнаружения и поисковые агенты

Поисковые API, Agent-Reach и другие агентные средства не входят в обязательный фундамент. Они могут находить релевантные страницы, публикации и документы после появления конкретного пробела. До сохранения первичного материала результат такого поиска не является фактом.

Фреймворки, предназначенные для поиска вакансий или иной предметной области, не следует включать только из-за слова `search`: применимость определяется моделью данных, происхождением результата и пользой для расследования.
