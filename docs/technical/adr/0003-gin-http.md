# ADR-0003. Gin как HTTP-адаптер MVP

- **Статус:** accepted
- **Дата:** 2026-09-19
- **Владельцы:** tech-lead, backend

## Контекст

Команда знакома с Gin. Между Gin и chi нет значимой для ожидаемой нагрузки разницы; важнее скорость разработки и изоляция транспорта от бизнес-логики.

## Решение

Использовать Gin для публичного REST API. Handlers выполняют валидацию транспорта, вызывают application services и преобразуют результат в DTO. Предметные модули не зависят от Gin.

## Рассмотренные варианты

- chi;
- стандартный `net/http` без router framework;
- gRPC как внешний интерфейс.

## Последствия

- команда быстрее создаёт HTTP-слой;
- OpenAPI остаётся источником публичного контракта;
- gRPC может быть добавлен как внутренний transport без замены предметного слоя;
- middleware не должен содержать бизнес-логику.

## Условия пересмотра

Существенная проблема поддержки, несовместимость с выбранной генерацией OpenAPI или изменение состава команды.
