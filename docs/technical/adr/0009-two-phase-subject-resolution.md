# ADR-0009. Двухфазный поиск исходного контрагента

- **Статус:** accepted
- **Дата:** 2026-10-01
- **Владельцы:** tech-lead

## Контекст

Поиск по ФИО или названию может вернуть несколько людей и организаций либо единственный слабый результат. Запуск дорогого полного сбора по каждому варианту создаёт шум, лишние обращения к источникам и риск построить граф не того субъекта.

## Решение

Разделить начальный сценарий на `subject_discovery` и `enrichment`. Discovery ищет ограниченный набор кандидатов. Сильное правило без конфликтов допускает автоматическое решение; иначе создаётся версионированный `match_review` для пользователя. Принятое решение одной транзакцией фиксирует корневую сущность и создаёт enrichment jobs вместе с outbox.

Отдельная команда «продолжить» после решения не вводится. Единственный кандидат не выбирается автоматически только из-за отсутствия альтернатив.

## Рассмотренные варианты

- сразу запускать полный сбор по исходной строке;
- выполнять enrichment всех кандидатов;
- разделить discovery и enrichment на два независимых ресурса расследования;
- требовать ручного выбора в каждом случае.

## Последствия

- уменьшаются лишние запросы и ложные графы;
- появляется явная точка пользовательского контроля;
- нужны `stage`, `match_reviews`, версия review и назначение `source_jobs.purpose`;
- discovery-результаты необходимо сохранять и повторно использовать;
- транзакция решения становится критической границей согласованности.

## Условия пересмотра

Подтверждённая потребность вести несколько независимых исходных субъектов внутри одного расследования либо выполнять сравнительный enrichment нескольких кандидатов одновременно.
