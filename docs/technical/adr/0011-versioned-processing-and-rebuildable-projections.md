# ADR-0011. Версионируемая обработка и пересобираемые канонические проекции

- **Статус:** accepted
- **Дата:** 2026-10-02
- **Владельцы:** tech-lead, backend, data

## Контекст

GraphX должен повторно разбирать сохранённый artifact новой версией parser/mapper и отменять ошибочное сопоставление source record с entity. Если производные records, claims, names, identifiers и relationships обновлять на месте, теряются воспроизводимость и возможность корректно удалить последствия ошибочного решения.

## Решение

Каждая обработка artifact фиксируется отдельным `processing_run`. `source_records` и `claims` относятся к конкретному run и не перезаписываются результатами следующего запуска. Один завершённый run выбирается активным для текущей материализации, а прежний сохраняется в истории.

`entity_records` с `unlinked_at IS NULL` является источником истины об актуальных сопоставлениях. `entity_names`, `entity_identifiers`, `relationships` и состав расследования считаются пересобираемыми проекциями активных claims и mappings. Отмена решения закрывает mapping и запускает детерминированный пересчёт затронутых проекций. Artifacts, source records, claims и решения физически не удаляются.

В MVP не выполняется необратимое физическое слияние двух канонических entities. Если позднее потребуется самостоятельная операция entity merge/split, она получит отдельную модель и ADR.

## Рассмотренные варианты

- перезаписывать записи и claims новой версией parser;
- хранить только последнюю версию обработки;
- удалять зависимые отношения при отмене mapping вручную;
- сразу реализовать универсальный merge/split графа.

## Последствия

- добавляется `processing_runs` и ссылка records на run;
- уникальность source record определяется внутри processing run;
- материализация обязана быть идемпотентной;
- relationship сохраняется, пока у него есть хотя бы один допустимый supporting claim;
- отмена mapping проверяется интеграционным тестом с пересборкой names, identifiers, relationships и derived DTO.

## Условия пересмотра

Подтверждённая потребность редактировать исходные claims, совместно курировать канонический граф или выполнять полноценный entity merge/split между несколькими расследованиями.
