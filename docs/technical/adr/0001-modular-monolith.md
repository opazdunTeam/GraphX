# ADR-0001. Модульный монолит и отдельные воркеры

- **Статус:** accepted
- **Дата:** 2026-09-19
- **Владельцы:** project-team

## Контекст

Команда состоит из трёх разработчиков. Предметные границы ещё уточняются, а ценность MVP определяется качеством конвейера данных, а не независимым масштабированием множества серверных компонентов.

## Решение

Публичный Go API реализуется модульным монолитом. Получение и разбор внешних материалов выполняются отдельными Python worker-процессами. Компоненты взаимодействуют через версионируемые контракты и RabbitMQ.

## Рассмотренные варианты

- микросервисы по каждому предметному модулю;
- монолит целиком на Python;
- единый процесс Go/Python без очереди.

## Последствия

- меньше deployable units и распределённых отказов;
- предметные модули должны сохранять явные границы;
- нестабильные источники изолированы от публичного API;
- выделение нового сервиса требует отдельной ADR и измеримой причины.

## Условия пересмотра

Независимый цикл релиза, подтверждённая потребность масштабирования, особая модель безопасности или необходимость изоляции сбоя.
