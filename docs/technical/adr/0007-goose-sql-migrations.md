# ADR-0007. goose и ручные SQL-миграции

- **Статус:** accepted
- **Дата:** 2026-09-19
- **Владельцы:** tech-lead, backend

## Контекст

Схема использует PostgreSQL extensions, индексы `pg_trgm`, ограничения, outbox и временные поля. Автоматическая генерация схемы ORM не даёт достаточного контроля ревью и порядка изменений.

## Решение

Использовать `goose` как отдельную CLI-утилиту. Все миграции, включая стартовые, писать вручную на SQL и запускать отдельным шагом до переключения версии API.

## Рассмотренные варианты

- GORM AutoMigrate;
- миграции при старте каждого API instance;
- Atlas;
- golang-migrate.

## Последствия

- SQL-схема и индексы явно видны в review;
- разработчики отвечают за Up/Down и совместимость релиза;
- миграции не зависят от ORM-моделей;
- требуется установленный `goose` или отдельный migration image.

## Условия пересмотра

Недостаточность goose для принятого процесса либо переход на schema-as-code после отдельного сравнения и ADR.
