# Архитектура интерфейса

## 1. Цель MVP

Интерфейс демонстрирует основной сценарий без регистрации, личного кабинета и декоративной сложности. Он должен позволить:

1. ввести ФИО и уточняющие признаки;
2. увидеть состояние каждого источника;
3. выбрать неоднозначного кандидата;
4. просмотреть компактные связи;
5. открыть временную шкалу;
6. проверить доказательство;
7. запросить расширение выбранной ветви.

## 2. Стек

- Vue 3 Composition API;
- TypeScript в строгом режиме;
- Vite;
- Vue Router;
- Pinia только для действительно общего клиентского состояния;
- сгенерированный из OpenAPI клиент;
- библиотека графа выбирается после прототипа минимальной выдачи.

Nuxt не используется в MVP. При появлении публичных индексируемых страниц или требования SSR переход оценивается отдельно.

## 3. Страницы

| Маршрут | Назначение |
|---|---|
| `/` | форма нового расследования |
| `/investigations/:id` | прогресс и частичный результат |
| `/investigations/:id/review` | решения по кандидатам |
| `/investigations/:id/result` | итоговая сводка, связи и время |
| `/investigations/:id/evidence/:evidenceId` | просмотр доказательства |

До появления авторизации URL расследования не считается средством защиты. Доступ ограничивается reverse proxy.

## 4. Состояние

- Серверное состояние не дублируется без необходимости в глобальном store.
- Polling включён только на незавершённой странице и останавливается при terminal state/уходе со страницы.
- Локальные фильтры графа и временной шкалы находятся в URL query или локальном состоянии.
- Решение пользователя отправляется отдельной командой и подтверждается ответом сервера.
- Optimistic update не используется для объединения сущностей: цена визуальной ошибки высока.

## 5. Представление результата

Минимальная отрисовка графа включает:

- имя/название узла;
- тип сущности;
- тип и направление связи;
- роль или должность;
- временной интервал или отметку «дата неизвестна»;
- визуальное различие факта, вычисленной связи и гипотезы;
- переход к доказательствам.

Не требуются сложная физика, анимации, трёхмерный граф и отображение всех найденных объектов одновременно. Рядом с графом сохраняется доступное табличное/списочное представление.

## 6. Ошибки и частичные результаты

- Недоступность одного источника показывается локально.
- Пользователь может просмотреть уже полученные результаты.
- Неизвестные enum и новые поля не ломают страницу.
- Технический `trace_id` доступен в подробностях ошибки.
- Повтор задания предлагается только если API разрешает действие.

## 7. Доступность и адаптивность

- Все действия доступны с клавиатуры.
- Цвет не является единственным способом различить уровень результата.
- Списки и доказательства читаемы без графа.
- На мобильном устройстве граф заменяется или дополняется последовательным списком связей.
- Минимальные состояния загрузки, пустой выдачи и ошибки проектируются сразу.

## 8. Расширение

После MVP допустимы SSE, Nuxt/SSR, сохранённые фильтры, совместная работа, отчёты и развитая визуализация. Они добавляются поверх стабильного API, а не через прямой доступ клиента к RabbitMQ или PostgreSQL.
