# Безопасность MVP

## 1. Границы

MVP не имеет регистрации и входа в само приложение. Это допустимо только для ограниченной демонстрации. Отсутствие прикладной авторизации не означает публичный неограниченный доступ.

Минимальная защита demo:

- HTTPS;
- закрытые от внешней сети PostgreSQL, RabbitMQ и MinIO;
- секреты вне Git;
- резервные копии и ограниченные сроки хранения.

Перед использованием несколькими внешними пользователями должна быть реализована нормальная идентификация, авторизация и изоляция расследований.

## 2. Сетевые границы

- Публичны только reverse proxy и необходимые HTTP routes.
- Management UI RabbitMQ и MinIO console не публикуются в Интернет.
- Workers не принимают публичные входящие соединения.
- Исходящий доступ browser worker ограничивается насколько это практично.
- Сервисы общаются во внутренней Docker network.

## 3. Секреты

- API keys, пароли, cookies и ключи MinIO/RabbitMQ не находятся в репозитории.
- Секрет не передаётся внутри сообщения RabbitMQ.
- Логи и exception messages проходят очистку.
- Demo-секреты ротируются после показа или подозрения на утечку.
- `.env.example` не содержит работающих значений.

## 4. Документы и внешние данные

- Ограничиваются размер, media type и время обработки.
- Имя файла пользователя не используется как путь хранения.
- Object key генерируется системой.
- Архивы имеют ограничения количества файлов и распакованного размера.
- HTML/PDF не исполняются в контексте основного API.
- Browser worker изолируется отдельным контейнером с минимальными правами.

## 5. SSRF и URL

Если worker получает URL:

- URL должен происходить из конфигурации источника или пройти allowlist;
- запрещаются loopback, link-local и внутренние адреса;
- redirect проверяется повторно;
- применяются timeout и предел ответа;
- пользователь MVP не может заставить сервер запросить произвольный URL.

## 6. Персональные данные

- собираются только данные, необходимые для расследования;
- источник и время получения сохраняются;
- лишние значения не попадают в логи и метрики;
- доступ к MinIO не является публичным;
- срок хранения и процедура удаления согласуются до реальной эксплуатации;
- чувствительная гипотеза не отображается как факт.

Этот документ не заменяет юридическую оценку условий источников и законодательства.

## 7. Зависимости и образы

- версии зависимостей фиксируются lock-файлами;
- контейнеры запускаются не от root, где это возможно;
- образы собираются из минимальных базовых образов;
- CI выполняет проверку известных уязвимостей до demo-релиза;
- обновление критической зависимости сопровождается тестами parser/contract.

## 8. Будущее расширение

При появлении учётных записей необходимо отдельно определить OIDC-провайдера, роли, tenant boundaries, аудит доступа, отзыв сессий и правила экспорта. Собственная реализация хранения паролей не является предпочтительным первым вариантом.
