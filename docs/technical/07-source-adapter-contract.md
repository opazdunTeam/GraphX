# Контракт адаптера источника

## 1. Назначение

Контракт позволяет добавлять источники независимо от канонической модели. Адаптер знает формат и правила доступа конкретного источника, но не решает, относятся ли две записи к одному реальному человеку или организации.

## 2. Состав адаптера

- **client/fetcher** — доступ к Bulk, API, HTTP, документам или браузеру;
- **parser** — преобразование исходного формата в записи источника;
- **mapper** — преобразование записи в атомарные claims общего формата;
- **metadata** — возможности, ограничения, частота запросов и версия;
- **fixtures/tests** — обезличенные или публично допустимые контрольные ответы.

## 3. Интерфейс SDK

Концептуальный Python-интерфейс:

```python
class SourceAdapter(Protocol):
    metadata: SourceMetadata

    async def collect(self, request: CollectRequest, context: AdapterContext) -> CollectResult:
        ...
```

`AdapterContext` предоставляет:

- HTTP-клиент с тайм-аутами;
- rate limiter;
- сохранение artifact;
- structured logger;
- trace/correlation context;
- проверку отмены и deadline;
- публикацию прогресса;
- доступ к секретам только своего источника.

Адаптер не создаёт собственные подключения к RabbitMQ, MinIO и системе логирования в обход runtime SDK.

## 4. Метаданные

Каждый адаптер декларирует:

```text
source_id
adapter_version
supported_operations
access_modes
jurisdictions
entity_types
rate_limit_policy
cache_policy
requires_browser
license_notes
```

`supported_operations`: `search_person`, `search_organization`, `fetch_record`, `fetch_document`, `bulk_sync`. Неподдерживаемая операция завершается постоянной типизированной ошибкой.

## 5. Приоритет способов доступа

1. официальный Bulk;
2. официальный документированный API;
3. доступные документы и выгрузки;
4. устойчивые HTTP-запросы и HTML;
5. Playwright;
6. поисковый провайдер только для обнаружения первичного материала.

Адаптер не обходит CAPTCHA, аутентификационные ограничения и технические запреты. Смена способа доступа отражается в карточке источника и тестах.

## 6. Artifact

Материал сохраняется до интерпретации. Метаданные включают:

- source URI или внешний идентификатор;
- время получения;
- дату публикации, если она известна;
- media type и размер;
- SHA-256;
- HTTP status и значимые headers без секретов;
- параметры запроса в безопасном виде;
- версию адаптера;
- условия лицензии/доступа при необходимости.

HTML или API response сохраняется до очистки. Если сохранение полного ответа запрещено условиями источника, адаптер явно возвращает ограниченное evidence и соответствующее предупреждение.

## 7. SourceRecord

SourceRecord отражает запись так, как её понимает источник:

```json
{
  "schema_version": 1,
  "source": "icij",
  "external_record_id": "...",
  "record_type": "person",
  "artifact_id": "uuid",
  "raw_data": {},
  "observed_at": "2026-09-19T12:00:00Z",
  "parser_version": "icij/0.1.0"
}
```

Значимые поля нельзя молча отбрасывать. Неизвестное поле остаётся в `raw_data`, пока для него не появится согласованное отображение.

## 8. Claim

Mapper выдаёт минимальные утверждения, например:

```json
{
  "claim_type": "person_name",
  "subject_local_ref": "person:123",
  "predicate": "name",
  "object": {"type": "string", "value": "Alexander Klebanov"},
  "validity": null,
  "evidence": {
    "artifact_id": "uuid",
    "locator": {"type": "json_pointer", "value": "/name"}
  }
}
```

Связь человек—организация представляется claim с двумя локальными ссылками, ролью и доступными временными границами. Mapper не заменяет неизвестную дату датой получения.

## 9. Типы ошибок

Все исключения преобразуются в один из контрактных кодов:

- `SOURCE_TIMEOUT`;
- `SOURCE_RATE_LIMITED`;
- `SOURCE_UNAVAILABLE`;
- `SOURCE_ACCESS_DENIED`;
- `SOURCE_ACTION_REQUIRED`;
- `SOURCE_FORMAT_CHANGED`;
- `DOCUMENT_UNSUPPORTED`;
- `CONTRACT_VALIDATION_FAILED`;
- `INTERNAL_ADAPTER_ERROR`.

Ответ с нулём записей — успешный результат `not_found`, а не исключение.

## 10. Тесты адаптера

Для принятия адаптера обязательны:

- fixture исходного ответа;
- тест parser;
- тест mapping claims и evidence locator;
- тест пустого результата;
- тест временной ошибки;
- тест изменения/отсутствия обязательного поля;
- контрактная валидация результата;
- отдельный, не блокирующий сборку smoke-тест живого источника.

Секреты и персональные данные из закрытых материалов не коммитятся. Изменение fixture должно сопровождаться объяснением изменения формата источника.

## 11. Добавление источника

1. Проверить применимость, условия доступа и лицензию.
2. Заполнить карточку в продуктовом каталоге источников.
3. Реализовать metadata и одну минимальную операцию.
4. Сохранить artifact и fixture.
5. Реализовать parser без канонизации.
6. Реализовать mapping в claims.
7. Пройти контрактные тесты.
8. Проверить источник на контрольном лице/организации.
9. Включить source feature flag для демонстрационного окружения.
