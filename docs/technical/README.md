## Машиночитаемые контракты

По мере реализации рядом с кодом создаются:

- `contracts/openapi.yaml` — HTTP API;
- `contracts/asyncapi.yaml` — каталог сообщений RabbitMQ после стабилизации схем;
- `contracts/schemas/*.json` — JSON Schema полезной нагрузки сообщений и результатов адаптеров;
- `db/migrations/` — фактическая схема PostgreSQL.

Markdown объясняет правила и причины. Машиночитаемый контракт и миграции определяют точный формат реализованного интерфейса. Расхождения устраняются в том же pull request, в котором меняется код.

## Основные сокращения

- **ADR (Architecture Decision Record)** — отдельная запись о значимом архитектурном решении: контекст, выбранный вариант, альтернативы и последствия.
- **DLQ (Dead Letter Queue)** — очередь сообщений, которые не удалось корректно обработать после допустимых повторов либо которые нарушают контракт.
- **ERD (Entity–Relationship Diagram)** — диаграмма таблиц/сущностей и связей между ними.
- **DTO (Data Transfer Object)** — структура данных на границе API, не равная внутренней предметной сущности.

## Статусы

- `draft` — рабочий черновик;
- `review` — документ передан на согласование;
- `approved` — решение принято командой;
- `deprecated` — документ заменён и содержит ссылку на замену.
