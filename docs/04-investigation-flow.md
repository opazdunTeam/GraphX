# Ход расследования

## Состояния верхнего уровня

Расследование имеет жизненный цикл и текущий этап. Это разные вещи.

Жизненный цикл `status`:

- `created` - создано, задания ещё не начались;
- `running` - работа продолжается или ожидается решение пользователя;
- `completed` - обязательный сценарий завершён;
- `completed_partial` - результат есть, но часть источников недоступна или завершилась ошибкой;
- `failed` - системная ошибка не позволила получить полезный результат;
- `cancelled` - пользователь отменил расследование.

Текущий `stage`:

- `subject_discovery`;
- `subject_resolution`;
- `enrichment`;
- `analysis`;
- `completed`.

Необходимость действия пользователя определяется наличием открытого review, а не отдельным статусом расследования.

### Переходы расследования

| Текущее состояние      | Допустимое следующее состояние | Условие                                                                                          |
| ---------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------ |
| `created`              | `running`                      | Создано первое задание                                                                           |
| `created`              | `cancelled`, `failed`          | Пользователь отменил запуск или старт завершился системной ошибкой                               |
| `running`              | `completed`                    | Все запланированные задания завершены, блокирующих reviews нет, постоянных ошибок источников нет |
| `running`              | `completed_partial`            | Полезный результат получен, но хотя бы один источник остался `unavailable` или `failed`          |
| `running`              | `failed`                       | Полезного результата нет и продолжение невозможно из-за системной ошибки                         |
| `running`              | `cancelled`                    | Пользователь отменил расследование                                                               |
| Терминальное состояние | -                              | `completed`, `completed_partial`, `failed` и `cancelled` автоматически не возобновляются         |

Пока существует открытый блокирующий review или задание, которое ещё может завершиться, расследование остаётся `running`. `not_found` считается корректным ответом источника и само по себе не приводит к `completed_partial`.

### Переходы задания источника

| Текущее состояние      | Допустимое следующее состояние                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `pending`              | `queued`, `running`, `retry_wait`, `succeeded`, `not_found`, `action_required`, `unavailable`, `failed`, `cancelled` |
| `queued`               | `running`, `retry_wait`, `succeeded`, `not_found`, `action_required`, `unavailable`, `failed`, `cancelled`           |
| `running`              | `retry_wait`, `succeeded`, `not_found`, `action_required`, `unavailable`, `failed`, `cancelled`                      |
| `retry_wait`           | `pending`, `cancelled`                                                                                               |
| `action_required`      | `pending`, `failed`, `cancelled`                                                                                     |
| Терминальное состояние | переходов нет                                                                                                        |

Прямой переход из `pending` или `queued` в рабочее либо итоговое состояние допустим, потому что результат может прийти раньше, чем publisher успеет записать `queued`, а событие `started` в первом срезе необязательно. Полученный результат сам доказывает, что команда была опубликована. `succeeded`, `not_found`, `unavailable`, `failed` и `cancelled` являются терминальными. Все переходы выполняет Go в транзакции с проверкой текущего статуса и `attempt_no`; позднее сообщение не может вернуть терминальное задание в работу.

## Первая фаза: поиск исходного объекта

1. API принимает ФИО, название и доступные уточнения.
2. Ввод нормализуется, но оригинал сохраняется.
3. Планировщик создаёт ограниченные discovery-задания.
4. Источники возвращают кандидатов и доказательства.
5. Go формирует версионированный review.
6. Сильный кандидат без конфликтов может быть выбран автоматически.
7. В остальных случаях пользователь подтверждает или отклоняет кандидата.

Единственный найденный кандидат не становится правильным только потому, что других нет.

## Вторая фаза: подробный сбор

Выбор кандидата сразу продолжает расследование:

1. создаётся или переиспользуется корневая каноническая сущность;
2. выбранная запись связывается с ней;
3. планируются enrichment-задания;
4. извлекаются организации, роли, идентификаторы, события и документы;
5. новые записи проходят сопоставление;
6. строятся фактические отношения;
7. поверх фактов применяются прозрачные аналитические правила.

Отдельная кнопка "начать полный сбор" после выбора кандидата не нужна.

## Частичный результат

Интерфейс показывает результат по мере готовности. Для каждого источника видны:

- текущее состояние;
- число попыток;
- время последнего изменения;
- найден ли результат;
- понятная ошибка;
- можно ли повторить действие;
- требуется ли участие пользователя.

`not_found`, `unavailable` и `failed` имеют разный смысл и не смешиваются.

## Расширение графа

Автоматически исследуется только ограниченная область вокруг исходного объекта. Пользователь может запросить расширение конкретной ветви, если видит полезную организацию или человека.

Расширение создаёт новые задания с `purpose = branch_expansion`, но использует уже сохранённые материалы и сущности, когда это возможно.

## Отмена и поздние результаты

После отмены новые канонические объекты и отношения к расследованию не добавляются. Поздний результат допускается зарегистрировать как полученное сообщение и artifact с `applied = false`, чтобы не потерять уже полученный материал и понимать его судьбу.

Позднее событие `started` или `retry_scheduled` не может вернуть терминальное задание в работу. Результат старой попытки не заменяет уже принятый результат новой попытки.

## Что получает пользователь

Итог расследования включает:

- карточку исходного объекта;
- варианты имени и идентификаторы;
- компактный граф фактических и вычисленных связей;
- временную шкалу;
- отдельную маркировку гипотез;
- список конфликтов и неизвестных периодов;
- состояние каждого источника;
- переход от объекта или связи к доказательству.
